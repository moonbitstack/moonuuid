Constants the package exports: the nil and max identifiers, the four namespaces, and the offset between the Gregorian and Unix epochs.

100-nanosecond intervals between 1582-10-15, where version 1 and 6 timestamps start, and 1970-01-01.

Functions

Free functions that read text or make one version each.

parsefunctionfn parse(text : StringView) -> Uuid raise Refused

Text in any of the spellings in use: canonical, with or without hyphens, in braces, with the urn:uuid: prefix; any case.

ticks_offunctionfn ticks_of(unix_nanos : Int64) -> Int64

A version 1 or 6 timestamp from nanoseconds since 1970.

v1functionfn v1(ticks~ : Int64, clock_seq~ : Int32, node~ : Int64) -> Uuid

Time-based: a 60-bit timestamp from ticks_of, a 14-bit clock sequence and a 48-bit node, laid out with the low time bits first.

v3functionfn v3(space : Uuid, name : StringView) -> Uuid

Name-based with MD5: the same namespace and name always give the same identifier. The name is hashed as UTF-8.

v4functionfn v4(random : BytesView) -> Uuid raise Refused

Random: 122 of the 16 bytes given are kept.

v5functionfn v5(space : Uuid, name : StringView) -> Uuid

Name-based with SHA-1, preferred over version 3.

v6functionfn v6(ticks~ : Int64, clock_seq~ : Int32, node~ : Int64) -> Uuid

Version 1's fields with the timestamp's high bits first, so the identifiers sort in time order.

v7functionfn v7(millis~ : Int64, random : BytesView) -> Uuid raise Refused

Milliseconds since 1970 in the top 48 bits, then 74 bits from the 10 random bytes given: a 42-bit counter whose top bit starts clear, so a generator can count up within a millisecond, and 32 random bits.

v8functionfn v8(custom : BytesView) -> Uuid raise Refused

Custom: 122 bits of the 16 bytes given, laid out as the caller likes; only version and variant are written over.

Types

The identifier and the generator, with the methods that read or write them.

Generatorstructstruct Generator

Identifiers from a clock and a source of random bytes the caller supplies, keeping what the time-based versions need between calls: version 1 and 6 timestamps never repeat or go back, and version 7 ids made within one millisecond count up, so they sort in the order made.

fn Generator::new(clock~ : () -> Int64, random~ : (Int32) -> Bytes) -> Generator

clock gives nanoseconds since 1970; random gives that many random bytes.

fn Generator::v1(self : Generator, node~ : Int64, clock_seq? : Int32) -> Uuid raise Refused

Version 1 with node; the clock sequence is random unless given.

fn Generator::v4(self : Generator) -> Uuid raise Refused

Version 4 from 16 random bytes.

fn Generator::v6(self : Generator, node~ : Int64, clock_seq? : Int32) -> Uuid raise Refused

Version 6 with node; the clock sequence is random unless given.

fn Generator::v7(self : Generator) -> Uuid raise Refused

Version 7. Within one millisecond the counter goes up by one with a fresh random tail; when the clock steps back, the millisecond after the last one is used; when the counter runs out, the millisecond moves on.

Uuidstructstruct Uuid

A 128-bit identifier as RFC 9562 lays it out. Compared, hashed and ordered by its bytes, so a sorted list of time-ordered ids is in time order.
